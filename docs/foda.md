# Análisis FODA

FODA del equipo y del proyecto, no del negocio imaginario de Bella Piel, que
no tiene FODA propio porque no existe fuera del ejercicio. Sirve para
evaluar la viabilidad del equipo de llegar a la Carpeta de Proyecto V1
completa en las 8 semanas del bimestre, y para derivar estrategias antes de
seguir avanzando.

## Matriz

|  | Positivo | Negativo |
|---|---|---|
| Interno (el equipo lo controla) | Fortalezas | Debilidades |
| | F1. El repositorio, la metodología y las guías por etapa (`.claude/skills/`) están armadas y ordenadas desde la Jornada 1. | D1. La bitácora individual no se actualiza al ritmo real del trabajo y puede quedar desalineada con el estado del repo. |
| | F2. Herramientas conectadas (Miro, Figma, GitHub) que aceleran diagramación y maquetado. | D2. Al ser Bella Piel un caso imaginario, no hay relevamiento real que valide las hipótesis del diagnóstico: todo se apoya en datos inventados por el equipo. |
| | F3. El equipo avanzó más rápido de lo previsto: árboles, MML, requerimientos y maquetado ya tienen borrador en la semana 3, antes de lo que marca el cronograma. | D3. Los roles recién se definieron en la semana 3, no desde el arranque. |
| Externo (solo influible indirectamente) | Oportunidades | Amenazas |
| | O1. La cátedra da una rúbrica clara y material de referencia (videos, teoría de Marco Lógico) que reduce la ambigüedad sobre qué se evalúa. | A1. Bimestre de solo 8 semanas, poco margen si algo se traba. Permanente: no depende de una debilidad propia. |
| | O2. Revisión cruzada entre equipos prevista en el marco pedagógico: feedback externo antes de la entrega final. | A2. Dependencia de herramientas externas (Miro, Figma, GitHub) para tener el proyecto al día; si cambia el acceso, se frena el trabajo. Permanente. |
| | O3. Documentar con asistencia de IA permite iterar rápido sobre cada pieza sin perder trazabilidad entre etapas. | A3. Si no se deja explícito que Bella Piel es un caso imaginario, la devolución del docente puede cuestionar la validez del diagnóstico. Circunstancial: asociada a D2. |

## Estrategias

- E1 (F1 + O1), ofensiva: usar la organización ya armada del repo para
  responder punto por punto a la rúbrica de Buenos Aires Aprende, mostrando
  trazabilidad explícita (causa → objetivo → componente → requerimiento →
  pantalla) en cada entrega.
- E2 (F2 + O3), ofensiva: aprovechar Miro y Figma para iterar rápido durante
  la revisión cruzada, llevando versiones actualizadas a cada instancia de
  coevaluación en vez de capturas viejas.
- E3 (F1 + A1), defensiva: con la metodología y las guías ya listas, el
  equipo absorbe mejor un imprevisto dentro del bimestre corto, sin
  reconstruir el criterio de trabajo si alguien falta una semana.
- E4 (D3 + O2), reordenamiento: ya se definieron los roles (ver issues del
  repo); falta que cada uno los asuma antes de la próxima revisión cruzada,
  para llegar con papeles claros a esa instancia.
- E5 (D2 + A3), supervivencia: dejar explícito en cada documento (ya hecho en
  `docs/propuestas.md` y `docs/01-arbol-de-problemas.md`) y repetirlo en el
  pitch que Bella Piel es un caso imaginario, para que la cátedra evalúe el
  proceso metodológico, no la existencia de un relevamiento que nunca fue.
- E6 (D1 + A1), supervivencia: actualizar `docs/bitacora.md` al cierre de
  cada jornada real de trabajo, para no perder tiempo del bimestre corto
  reconstruyendo qué se hizo y qué falta.

## Qué falta

- Que cada integrante confirme su rol asignado (ver issues del repo).
- Revisar este FODA después de la primera revisión cruzada con otro equipo,
  para ver si O2 se cumplió como se esperaba.
